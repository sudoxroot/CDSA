
# Windows Event Logging Basics

## What are Windows Event Logs?

Windows continuously records everything happening on the system.

Think of it as a **security camera** for Windows.

It logs events such as:

- User logins
    
- Program crashes
    
- Service starts/stops
    
- File access
    
- Policy changes
    
- Malware detections
    
- Network activity
    

SOC analysts use these logs to reconstruct what happened during an incident.

---

# Where are logs stored?

Open:

```text
Event Viewer
```

You'll see several log categories.

| Log              | Contains                                |
| ---------------- | --------------------------------------- |
| Application      | Application errors and information      |
| Security         | Authentication, authorization, auditing |
| System           | Windows OS events                       |
| Setup            | Windows installation and updates        |
| Forwarded Events | Logs collected from other computers     |

---

## Application Log

Contains events generated by software.

Example:

```text
Chrome crashed.

↓

Application Log
```

Useful for:

- Application failures
    
- DLL errors
    
- Service crashes
    

---

## Security Log  (Most Important)

Contains security-related events.

Examples:

- User logon
    
- User logoff
    
- Account creation
    
- Password changes
    
- Privilege escalation
    
- Group membership changes
    

This is the **primary log SOC analysts investigate**.

---

## System Log

Contains operating system activity.

Examples:

- Driver loaded
    
- Windows boot
    
- Windows shutdown
    
- Service started
    
- Hardware failure
    

Useful for detecting:

- Unexpected reboots
    
- Driver issues
    
- Service manipulation
    

---

## Setup Log

Contains:

- Windows installation
    
- Feature updates
    
- Upgrade events
    

Mostly useful during troubleshooting.

---

## Forwarded Events

Used when multiple computers send logs to one central server.

Instead of checking:

```text
PC1

PC2

PC3

PC4
```

The administrator views:

```text
Forwarded Events
```

Everything is centralized.

---

# Anatomy of a Windows Event

Every event contains several important fields.

---

## 1. Log Name

Example:

```text
Security
```

Tells you where the event came from.

---

## 2. Source

The component that generated the event.

Example:

```text
Microsoft-Windows-Security-Auditing
```

or

```text
SideBySide
```

---

## 3. Event ID 

The most important identifier.

Example:

```text
4624
```

means

> Successful Logon

Another example:

```text
4625
```

means

> Failed Logon

SOC analysts often search by Event ID first.

---

## 4. Task Category

Describes the type of operation.

Example:

```text
Logon
```

or

```text
User Account Management
```

---

## 5. Level

Severity of the event.

| Level       | Meaning                        |
| ----------- | ------------------------------ |
| Information | Normal activity                |
| Warning     | Something unusual              |
| Error       | Failure occurred               |
| Critical    | Serious system issue           |
| Verbose     | Detailed debugging information |

---

## 6. Keywords

Extra classification tags.

Security log examples:

```text
Audit Success
```

or

```text
Audit Failure
```

Useful for filtering events.

---

## 7. User

Which account triggered the event.

Example:

```text
Administrator
```

or

```text
SYSTEM
```

---

## 8. OpCode

Describes the specific operation.

Usually less important for Tier 1 analysts.

---

## 9. Time Created

Exactly when the event occurred.

Critical for building an attack timeline.

---

## 10. Computer

Which machine generated the event.

Example:

```text
DC01
```

---

## 11. XML Data 

Everything in the event is stored as XML.

Example:

```xml
<EventData>
    <Data Name="TargetUserName">
        Administrator
    </Data>
</EventData>
```

The XML view often contains fields not shown in the standard display.

---

# Event ID 4624 - Successful Logon

Probably the most common Windows Security event.

Meaning:

> Someone successfully logged in.

Example:

```text
User:
Administrator

Event ID:
4624
```

---

## Important Fields

### Logon ID

Example:

```text
0x3E7
```

Think of it as a **session ID**.

Every action performed during that login session can be correlated using the same Logon ID.

Example:

```text
4624 Login

↓

4672 Special Privileges

↓

4688 Process Created

↓

All share Logon ID
0x3E7
```

This helps reconstruct a user's activity.

---

## Logon Type 

One of the most important fields.

| Type | Meaning                      |
| ---- | ---------------------------- |
| 2    | Interactive (keyboard login) |
| 3    | Network (SMB, file shares)   |
| 4    | Batch job                    |
| 5    | Service                      |
| 7    | Unlock workstation           |
| 8    | NetworkCleartext             |
| 9    | NewCredentials (`runas`)     |
| 10   | Remote Desktop (RDP)         |
| 11   | Cached credentials           |

Example:

```text
4624

Logon Type:
10
```

Means:

Remote Desktop login.

---

# Event Correlation Using Logon ID

One event is rarely enough.

Suppose:

```text
4624
```

shows

```text
Logon ID:
0x3E7
```

You can search all events with

```text
SubjectLogonId=0x3E7
```

Now you may discover:

```text
4624 Login

↓

4672 Special Privileges

↓

4688 PowerShell

↓

4698 Scheduled Task

↓

4702 Task Modified
```

Instead of isolated events, you now have an attack timeline.

---

# XML Filtering

The Event Viewer allows custom XML queries.

Example:

```xml
SubjectLogonId='0x3E7'
```

This filters only events related to that login session.

Very useful during investigations.

---

# Example Investigation

Suppose you see:

```text
4624
```

SYSTEM logs in.

Later:

```text
4672
```

Special privileges assigned.

Then:

```text
4907
```

Audit policy changed.

Then:

```text
4688
```

PowerShell launched.

This sequence suggests:

```
SYSTEM Login
        ↓
Admin Privileges
        ↓
Audit Policy Modified
        ↓
PowerShell Started
```

The events together tell a much richer story than any single event alone.

# Event ID 4672 - Special Privileges Assigned

Meaning:

A user logged in with administrative privileges.

Common accounts:

- Administrator
    
- SYSTEM
    
- Domain Admins
    

Example privileges include:

- `SeDebugPrivilege`
    
- `SeBackupPrivilege`
    
- `SeRestorePrivilege`
    

### Is it always malicious?

No.

Administrators receive this event regularly.

Suspicious cases include:

- Unexpected user receiving it.
    
- Occurring at unusual times.
    
- Appearing after suspicious logons.

## Key Takeaways

- **Security logs** are the most valuable source for authentication and privilege-related investigations.
    
- **Event IDs** identify what happened, while fields like **Logon ID**, **Logon Type**, and **Computer** provide the context needed to investigate.
    
- **Correlating events** (especially using **Logon ID**) is essential—one event rarely tells the full story.
    
- Build a baseline of **normal activity** in your environment. The same event can be benign in one organization and suspicious in another.
    
- Focus on understanding **why an event occurs and when it becomes abnormal**, rather than trying to memorize hundreds of Event IDs. This approach will serve you much better in both the CPTS exam and real SOC investigations.

    ## Question 1
    
    
    ### Analyze the event with ID 4624, that took place on 8/3/2022 at 10:23:25. Conduct a similar investigation as outlined in this section and provide the name of the executable responsible for the modification of the auditing settings as your answer. Answer format: T_W_____.exe
    ## Solution:
    - RDP to the given IP address -> Open Event viewer -> Go for security log ( as given Event ID is always originated from security log) -> Filter the current log for Event ID 4624
    - checkout the log taking place on 8/3/2022 at 10:23:25, Here you'll try to find the executable file but there wouldn't be any.
    - so we'll check the related log by SubjectLogonID, which would be 0x3e7. This SubjectLogonID is for event ID 4907 (already mentioned in the section)
    - I filtered current log for event ID 4907 and check out again at 8/3/2022 at 10:23:25
    - There I got the executable responsible for the modification.
    - **Answer**: TiWorker.exe
- 
- **PRO TIP**:
  You might think why I didn't puzzled when I checked the log given in question, that was because there was another information (modification of the auditing settings). As, given log was only related to successful logons and not for modification of the auditing settings, Therefore, I hit on the idea that some other log would be related to the given log which should be responsible for modification of the auditing settings (like the event ID 4907)    
    
- ## Question 2
    
    ### Build an XML query to determine if the previously mentioned executable modified the auditing settings of C:\Windows\Microsoft.NET\Framework64\v4.0.30319\WPF\wpfgfx_v0400.dll. Enter the time of the identified event in the format HH:MM:SS as your answer.
    
    ## Solution:
    - this was a quite easy task, as we only have to open the Filter current log and then, modify the query:

```
<QueryList>
  <Query Id="0" Path="Security">
    <Select Path="Security">
      *[System[(EventID=4907)]] 
      and 
      *[EventData[Data[@Name='ObjectName']='C:\Windows\Microsoft.NET\Framework64\v4.0.30319\WPF\wpfgfx_v0400.dll']]
    </Select>
  </Query>
</QueryList>

```

- After applying the current filter, we'll get the filtered result and any of the result which will contain TiWorker.exe and run after the given time will be our targeted log and you will get the time there also.
**Answer:** 10:23:50
